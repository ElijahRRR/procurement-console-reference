# 接口与字段附录

本表是 2026-10-22 观察到的客户端协议。用于解释现有产品，不代表服务商提供了稳定、授权给外部应用使用的开放 API。状态为“源码”的接口没有在本轮调用。

基础路径：`https://smallbee168.com/prod-api`。网站管理端使用 Bearer 请求头；插件展示的请求封装没有显式添加同样的 Authorization。后端实际鉴权、来源限制、授权和幂等机制未知，不能据此宣称接口可匿名调用。

## 1. 网站订单端

以下路径以 `/system/amazonOrder` 为前缀。

|方法|后缀|用途|验证层级|
|---|---|---|---|
|POST|`/list`|分页检索订单|实测：账号内列表及两笔 AMZ 精确查询|
|GET|`/{id}`|读取单笔详情|源码|
|POST|空|新增|源码|
|PUT|空|修改|源码|
|DELETE|`/{id}`|删除|源码|
|POST|`/importOrder`|multipart 导入 Excel|源码、导入入口与公开模板|
|POST|`/export`|导出管理端订单|源码，blob，60 秒超时|
|POST|`/approvalOrder`|采购审批|源码|
|POST|`/updateOrderStatusBatch`|批量重置采购状态|源码|
|POST|`/updateRemark`|修改备注|源码|
|POST|`/updateAmzOrderNo`|回填/修改 AMZ 订单号|源码|
|POST|`/updateOrderProductAsin`|修改商品 ASIN|源码|
|POST|`/updateOrderReceivingInfo`|修改收货资料|源码|
|POST|`/updateBuyerInfo`|修改买家号及 customerId|源码|
|POST|`/updateShippingStatus`|更新发货标识|源码，不能据路径名认定会调用 Walmart|
|POST|`/queryOrderInfo`|运营物流查询|实测：错误键返回空数组，正确业务键返回两笔记录|
|POST|`/exportOrder`|物流查询页导出|源码|

`/list` 的查询参数是 `pageNum/pageSize`；请求 JSON 为：

```json
{
  "storeName": null,
  "orderNoList": null,
  "platformOrderNo": "AMZ-DEMO-A",
  "buyerAccount": null,
  "remark": null,
  "status": null,
  "orderStatus": null,
  "country": null,
  "createTimeStart": null,
  "createTimeEnd": null,
  "purchaseTimeStart": null,
  "purchaseTimeEnd": null
}
```

这是便于阅读的归一化示例，不是逐字保存的浏览器请求。空值字段可能被省略。分页结果外壳为 `total / rows / code / msg`。

查询页分别使用 `{"orders":["业务订单号"]}` 和 `{"orderNos":["业务订单号"]}` 请求查询及导出；两个字段名不同。

## 2. 插件任务和回传端

|方法|路径|主要输入|验证层级|
|---|---|---|---|
|GET|`/system/amazonOrder/getNeedPurchaseOrders`|customerId|源码；未触发领取任务|
|GET|`/system/amazonOrder/getNeedSyncOrders`|customerId|源码；未触发同步|
|GET|`/system/amazonOrderPig/getNeedSyncOrders`|customerId|源码|
|POST|`/system/amazonOrder/purchaseOrderFinishUpdate`|内部订单 ID、AMZ 号、商品、费用、日期、卡片、邮编|源码|
|POST|`/system/amazonOrder/updateOrderStatus`|orderId、status、failContent|源码|
|POST|`/system/amazonOrder/updateTrackingInfo`|订单、物流及证据字段，见下表|源码|
|POST|`/system/amazonOrderPig/updateTrackingInfo`|订单、轨迹、首事件时间、邮编、卡片|源码|
|POST|`/system/amazonOrder/updateAmzOrderStatus`|orderId、orderNumber、amzStatus|源码|
|POST|`/system/amazonOrder/updateBuyerCookie`|customerId、country、cookie|源码；未获取或发送真实 Cookie|

采购成功回传字段：

`id, platformOrderNo, asins, deliveryTime, origDeliveryTime, creditCardNumber, mainPostCode, extPostCode, shipping, totalBeforeTax, tax, total, products`。

其中 `products` 的客户端结构为 `asin / quantity / unitPrice / totalPrice / productImage`。它与订单列表中返回的商品结构不相同，不能直接互换。

主物流回传字段：

|分组|字段|备注|
|---|---|---|
|关联|orderId、asins、orderDate|AMZ 单号主要由任务上下文关联|
|物流|trackingNumber、trackingUrl、carrier|默认采集路径可能只使用首个包裹链接|
|时间|deliveryDate、origDeliveryDate|归一化日期与原始文案并存|
|事件|trackingJson|JSON 字符串或 null，不是直接数组|
|证据|trackingHtml、receiptPicture|HTML 的 Base64；签收图片 URL|
|核验|mainPostCode、extPostCode、card|邮编、卡片信息|
|费用|subtotal、shipping、totalBeforeTax、tax、total|留意列表 `subTotal` 与回传 `subtotal` 大小写不同|

`amazonOrderPig` 的物流载荷较小：`orderId, trackingNumber, trackingUrl, trackingHtml, firstEventTime, mainPostCode, card, trackingJson`。源码以轨迹数组最后一个事件的 day 与 time 拼成 firstEventTime，依赖事件排序；不能当成已规范化的时间戳。

通用请求函数检查 HTTP `response.ok` 后读取 JSON。获取采购任务额外检查 `code === 200`；部分回传成功日志没有相同业务码判断。采购成功回传的重试参数为 5 次、初始间隔 1 秒；状态与轨迹等通常为 3 次、初始间隔 1 秒。服务器去重保障未验证。

## 3. 订单列表字段字典

下表为真实列表响应所见字段，不是数据库结构。

|分组|字段|
|---|---|
|主键及关联|id、storeName、orderNo、platformOrderNo、buyerAccount、buyerCustomerId|
|操作记录|remark、createName、createTime、updateTime、purchaseTime|
|收货资料|receivingName、receivingCountry、receivingState、receivingCity、receivingDistrict、receivingAddress、receivingPhone、receivingPostCode|
|商品|asin、products|
|物流|platformTrackCarrier、platformTrackNo、deliveryTime、orderStatus、deliveryTimeAbnormal|
|金额|subTotal、shipping、totalBeforeTax、tax、total、paymentCard|
|采购执行|status、failContent|
|检查|platformPostCode、asinCheck、postCodeCheck、priceCheck|

真实返回中 `total` 为带美元符号的字符串（如虚构示例 `$10.00`），子商品 `price` 为数值。下游需要显式处理币种、金额精度、空值与原始文案，不能混合直接算总账。

子商品列表字段：`id, orderId, asin, country, quantity, imgUrl, price, status`。样本里 orderId/country 可为 null，因此不应把所有返回字段都设为必填。

公开查询的精简对象为：

```json
{
  "orderNo": "PO-DEMO-A",
  "platformOrderNo": "AMZ-DEMO-A",
  "asin": "ASIN-DEMO-A",
  "platformTrackCarrier": "USPS",
  "platformTrackNo": "TRACK-DEMO-A",
  "trackingJson": "[轨迹对象序列化后的字符串]",
  "receiptPicture": null,
  "deliveryTime": "2026-10-22",
  "orderStatus": 2
}
```

以上标识及数据为结构示例；下例演示轨迹对象的字段：

```json
{
  "day": "Wednesday, October 21",
  "time": "3:23 PM",
  "tracking_info": "Package left an Amazon facility.",
  "state": "XX",
  "city": "Example City"
}
```

源码出现 `/system/asinMonitor/list`（POST）、`/{id}`（GET/DELETE）、根路径（POST/PUT）、`/updateAsinSalePrice`（POST）以及导入 `/importData`、导出入口。页面展示 salePrice、亚马逊价格、profitAndLoss 等字段。当前账号为空列表；利润计算公式及后台更新机制未验证。

## 5. 与现有系统的名称对照

|业务含义|飞书样本|小蜜蜂|现有操作台|
|---|---|---|---|
|销售订单/销售行关联|平台订单号、order_line_id、主订单关联等字段|orderNo，实际可能是拼接键|WalmartOrder.purchase_order_id＋OrderLine.line_number／内部 ID|
|采购执行环境|买家号：环境 BUYER-DEMO|buyerAccount＋buyerCustomerId|采购方配置存在，具体买家会话关联需另行确认|
|供应方采购订单|AMZ 订单号|platformOrderNo|所查模型未见独立对应实体|
|包裹|买家物流单号|platformTrackNo|OrderLine.tracking_number|
|物流状态|订单状态选择项|orderStatus|需要转换到本系统订单/物流模型，不能硬拷贝状态数字|
|预计/实际送达|预计/签收时间|deliveryTime|建议区分语义，不能仅靠一个日期判断是否签收|

飞书的订单行关联值与新系统内部 ID 是否等价，接入时需核对。
