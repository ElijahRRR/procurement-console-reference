# 采购助手（浏览器插件）

采购控制台的浏览器插件：Chrome MV3 + TypeScript + Vite，本机 Chrome 与 AdsPower 浏览器环境都能加载。一个浏览器环境（一个 Chrome 用户，或一个 AdsPower 环境）装一份、配对一次。服务端与控制台的安装、启动和整体流程见仓库根目录的 [README](../README.md)。

**本版本只做模拟执行，不产生真实订单。** 插件领取服务端分配给本账号、已到采购日期的任务，按任务数据推出一份结算信息交给服务端护栏裁决，再走提交登记与结果上报；它不打开、不点击、不修改任何亚马逊页面。真实下单流程在后续 PR 加入，并且由服务端单独开关。

|能做的|说明|
|---|---|
|配对|设置页填写控制台生成的 8 位配对码，换取设备令牌（只存在插件后台的 IndexedDB 里，亚马逊页面上的内容脚本读不到）|
|心跳|每分钟一次，带上最新身份；缓存服务端下发的账号配置（执行方式、执行时间、额度、配送上限等）。打开面板、页面回到前台、点「刷新身份」、开始执行前都会马上同步一次；已配对还没绑定账号时 10 秒一次，控制台里一绑定，面板几秒内显示账号|
|身份识别|亚马逊页面上读登录状态与买家号 ID（customerId），多个标签页的读数按页面加载先后对账后上报服务端比对：一致 / 不一致 / 未登录 / 未知|
|结果回执|上报结果之前先存一份回执；服务端重启、断网、插件后台被回收时，服务端恢复后自动补交同一份结果（插件后台启动时、每次心跳成功时立即补交，另有 30 秒一次的退避补交），最多保留 24 小时|
|页面内面板|订单历史页默认展开，其他亚马逊页面右下角是收起的悬浮按钮|
|模拟执行|手动点「开始执行（模拟）」，或到了控制台配置的执行时间自动开始|

## 构建与测试

需要 Node.js 22（与根目录 README 一致；`npm test` 用到 `node --test` 的通配符与 `mock.timers`，Node 21 以下跑不了）。

```bash
cd extension
npm ci            # 按 package-lock.json 安装依赖
npm run build     # 类型检查 + 构建 → extension/dist（可直接「加载已解压的扩展程序」）
npm test          # 编译纯函数与协议客户端 → Node 单测（node --test）
npm run pack      # 构建并打包 → extension/release/采购助手-<版本>.zip（AdsPower 上传用）
```

`npm test` 覆盖：错误码与中止原因码的中文说明（界面上不出现原样的英文码）、执行时间换算（北京时间、跨日、与本机时区无关）、标签页租约裁决与串行闸、协议客户端（错误映射、ACCOUNT_BUSY 详情、只对「没说上话」与幂等接口的 5xx 重试、提交登记绝不自动重试、HTTP 200 也校验形状）、模拟执行引擎对着内存假服务端（`test/fake-server.mjs`，按开发契约 §4、§5 实现，边角路径照 `backend/services/execution.py` 的答复：护栏拦截即结束尝试、进度的 cancel_code、ABORTED_BY_SERVER 按中止类处理、身份超过 10 分钟没有上报即拒绝、领取后来源有变化、提交前复核护栏不过、稍后再领、重复上报回 duplicate、迟到回执 409、浏览器重发 POST 得到 409、结束批次的 detail）的各条路径、身份解析器对着导航栏夹具（`test/fixtures/`，虚构数据）、身份按页面加载先后对账、结果回执、清单权限，以及**真正的后台模块**对着假 chrome 环境（`test/fake-chrome.mjs`）跑：绑定后立即同步、配对被限速或被 Host 允许名单拒绝时的提示、执行页面刷新 / 关闭 / 不再答复时接管批次、回执补交的时机、执行中重报身份、定时到点先拿新配置、设备令牌不进 storage.local。

## 安装到本机 Chrome

1. 构建：`cd extension && npm ci && npm run build`，得到 `extension/dist`。
2. 在 Chrome 地址栏打开 `chrome://extensions`。
3. 打开右上角的「开发者模式」。
4. 点「加载已解压的扩展程序」，选择 `extension/dist` 文件夹（不是 `extension` 本身）。
5. 首次安装会自动打开设置页；之后也可以点工具栏的插件图标 →「打开设置」。

更新代码后重新 `npm run build`，再在 `chrome://extensions` 里点插件卡片上的刷新按钮，并刷新已打开的亚马逊页面（旧页面里的内容脚本已经和新后台断开）。

## 安装到 AdsPower

**AdsPower 里的具体菜单路径还没有核实过。** 下面的名称是常见叫法，不保证与你的 AdsPower 版本一致，请以客户端里实际看到的为准：

1. `npm run pack`，得到 `extension/release/采购助手-0.1.0.zip`。
2. 在 AdsPower 客户端里找到扩展管理（可能叫「扩展」「应用中心」或「插件」），选择添加自定义 / 本地扩展，上传上面的 zip（客户端要的是文件夹时，选 `extension/dist`）。
3. 把扩展分配给要使用的浏览器环境（可能可以按分组或逐个环境开启）。
4. 打开该环境，点工具栏的插件图标 →「打开设置」完成配对。每个环境单独配对、单独起设备名称。

如果 AdsPower 的浏览器允许打开 `chrome://extensions`，也可以按上面 Chrome 的步骤直接「加载已解压的扩展程序」选择 `extension/dist`。插件要求浏览器内核不低于 Chromium 103。

## 配对

1. 先在本机启动服务端（`cd backend && ../.venv/bin/python cli.py serve`，默认 `http://127.0.0.1:8790`；首次安装见根目录 README）。
2. 控制台「账号与设备」→「设备」→「生成配对码」（8 位，10 分钟内有效，只能用一次）。
3. 插件设置页填写：服务端地址（默认 `http://127.0.0.1:8790`；当前版本只支持本机，`http://127.0.0.1:<端口>` 或 `http://localhost:<端口>`）、配对码、设备名称（例如 `Mac-AdsPower-环境1`）、浏览器（Chrome / AdsPower / 其他），点「配对」。
4. 配对失败时设置页写明原因：
   - 「配对码无效或已过期」：重新在控制台生成一个。
   - 「尝试次数过多，请 N 秒后再试」：服务端按来源地址限制配对失败的次数（429 `RATE_LIMITED`），等 N 秒再试。
   - 「服务端不接受主机名 … 的请求」：服务端只接受本机地址（127.0.0.1、localhost）和环境变量 `PC_ALLOWED_HOSTS` 里登记的主机名（403 `FORBIDDEN`）。把服务端地址改成 `http://127.0.0.1:8790` 或 `http://localhost:8790`，或者请管理员把这个主机名加进服务端的 `PC_ALLOWED_HOSTS` 后重启服务端。
   - 「无法连接服务端」：服务端没启动，或地址、端口填错了。

「解除配对」只删除本浏览器里的设备令牌；要让服务端也作废，在控制台撤销该设备。还有结果回执没送到服务端时不能解除配对。

## 绑定买家账号

1. 配对成功后，在控制台「账号与设备」→「设备」里，在这个设备的「绑定账号」一栏选对应的买家账号。没绑定时插件每 10 秒同步一次，绑定后几秒内设置页、面板就显示绑定账号、身份状态和服务端下发的账号配置，「开始执行（模拟）」随即可点。
2. 在这个浏览器里登录绑定的亚马逊买家账号，打开任意亚马逊页面：插件读取登录状态与买家号 ID 并上报，身份状态变成「身份一致」后才能开始执行。
3. 账号还没登记买家号 ID 时显示「身份未知」：在控制台「设备」页点「采用此 ID」。
4. 服务端要求身份 10 分钟内上报过（`identity_fresh_s`，默认 600 秒）：开着亚马逊页面时插件每 2 分钟重读一次、每分钟心跳捎带一次；执行中引擎每 3 分钟、以及每次提交登记之前再让所有亚马逊标签页重读并上报一次。超过 10 分钟没有上报，服务端拒绝开始批次、不再下发任务，进行中的那一笔在提交前中止（不暂停账号）。

## 页面内面板

- 显示：服务端连接、设备名称、绑定账号、身份状态、「模拟模式」标签、今日额度、执行方式（定时则列出北京时间）、当前模拟结局、当前批次与尝试进度、待补交的结果回执、最近 50 行日志（北京时间）。
- 按钮：「开始执行（模拟）」、「刷新身份」；执行中变为「停止执行」（当前这一笔结束后停止）。
- 面板挂在封闭的 Shadow DOM 里，亚马逊页面的样式进不来，面板的样式也不影响页面。外观按 EasyQuick 设计系统（青绿主色、圆角、系统字体，跟随系统浅色 / 深色）。

## 定时执行

- 账号的执行方式为「定时」时，插件按控制台配置的执行时间（如 `14:00`）设闹钟，**一律按北京时间理解**，与电脑所在时区无关。
- 到点先同步一次心跳（缓存的配置最多一分钟前的，例如刚在控制台恢复执行），再决定开不开始；如果本浏览器有打开的亚马逊页面，就在该页面开始一个定时批次；没有的话，日志记一次「等待环境」。
- 本地记录说「本浏览器已在执行」时，先问执行页面引擎还在不在（页面可能已经刷新）：还在才「并入当前批次」，不在了先结束旧批次再开始定时批次。
- 错过的时间点在**同一个北京日期**内补执行一次：电脑开机、浏览器启动、打开亚马逊页面时都会检查；跨过北京时间零点不再补（方案 v2 默认值 4）。
- 每个时间点每天只处理一次。服务端拒绝（身份不一致、账号暂停、账号在别的设备上执行等）也算处理过，日志写明原因；没连上服务端、或占着账号的是本设备上一次还没到期的批次（刷新页面、插件更新之后），则稍后自动重试。
- 当天新增一个已经过去的执行时间，会被当作「今天错过的」立即补执行一次。

## 模拟执行做什么

**不产生真实订单。** 插件不打开、不点击、不修改任何亚马逊页面；只有「读结算页」这一步是按任务数据推出来的，服务端的护栏、提交登记、结果处理、额度与状态机全部走真实代码路径。服务端本阶段也拒绝非模拟批次。按开发契约 §5 一步一步走：

1. `POST /runs {trigger, simulated: true}` 开始批次（409 `ACCOUNT_BUSY` 时显示占用的设备与开始时间）。开始之前让每个亚马逊标签页重读身份、对账、上报；各标签页显示的登录账号不一致时不开始。
2. 循环 `POST /runs/{id}/next` 领取，直到没有任务（`attempt: null`）。候选任务只是暂时被别的操作（导入、同步、分配）锁着时，服务端回 `attempt: null` 且带 `retry_after_s`：插件等这么久（夹在 1 – 30 秒之间）再领，最多再领 6 次，等待期间照常续租，不结束批次；6 次之后仍被占用就以 `completed` 结束本批次。
3. 每一笔：进度（开始、读结算信息）→ 护栏（模拟的结算事实）→ 上报一次新鲜的身份（`POST /plugin/v1/identity`）→ 登记前最后一次进度确认 → 提交登记（只认 HTTP 200，绝不自动重试）→ 上报结果。
4. `POST /runs/{id}/finish {reason: "finished", detail}` 结束批次（`detail` 是插件的细分原因：completed、stopped、attempt_cap、result_unknown、submit_rejected……，服务端记进批次结束事件的 `plugin_detail`）。期间按服务端给的租约有效期续租：每 min(35 秒, 有效期 / 3) 一次，每一步之前到点就补一次。

进度返回 `continue=false` 时插件不走护栏与登记，按服务端给的机读原因 `cancel_code` 上报中止，继续下一笔：

|`cancel_code`|含义|插件上报|服务端处理|
|---|---|---|---|
|`UPSTREAM_CANCELLED`|上游已取消|`ABORTED_UPSTREAM_CANCELLED`|尝试中止，任务取消|
|`ACCOUNT_ARCHIVED`、`ACCOUNT_PAUSED`|账号已归档、已暂停执行|`ABORTED_BY_SERVER`|尝试中止，任务回到已分配；不暂停账号，不占额度|
|`IDENTITY_MISMATCH`、`IDENTITY_STALE`|身份不符、超过 10 分钟没有上报身份|`ABORTED_BY_SERVER`|同上|
|`SOURCE_HOLD`、`SOURCE_CHANGED`|来源把任务暂停了、领取后来源有变化|`ABORTED_BY_SERVER`|同上，再按来源变化重新定状态（可能进待确认或待核实）|
|`ATTEMPT_FINISHED`|这一笔服务端已经结束了|不再上报|—|

服务端没给 `cancel_code`（旧版本服务端）时只报它认得的 `ABORTED_UPSTREAM_CANCELLED`。日志与 `error_detail` 里写服务端的中文原话。

提交登记被拒（409）时：服务端说已登记（`detail.attempt_status` 为 submitting / verifying，浏览器在连接断开后重发了同一个 POST）→ 上报 `unknown` 并结束批次；按最新配置复核护栏不过（`GUARD_BLOCKED`）→ 按 `detail.block_code` 上报失败（没给时报 `GUARD_BLOCKED`），计拦截，继续下一笔；其他（上游已取消、账号暂停、身份不符或过期、来源有变化 `SOURCE_CHANGED`……）→ 再问一次进度，按上表的 `cancel_code` 上报中止；进度仍说继续才报 `SUBMIT_REJECTED`。

模拟的结算事实：小计 = 采购单价 × 数量（按整数分计算），运费 0，税费 0，总额 = 小计，送达日期 = 洛杉矶今天 + min(3, 配送上限)，邮编取任务的，卡尾号取账号期望卡尾号（未设置则为空），币种 USD，配送方 amazon。成功时单号为 `SIM-<北京日期 YYYYMMDD>-<尝试 ID>`（尝试 ID 是服务端的 attempt_id，不是「第 N 次尝试」的序号）。模拟结果不写回飞书，可在控制台「清除模拟结果」。

设置页可以选模拟结局，用来验证服务端的各条处理路径：

|模拟结局|插件的动作|服务端应有的结果|
|---|---|---|
|正常通过（默认）|护栏放行 → 登记 → 上报成功|任务「已采购」|
|结算总额超过限价|总额 = 限价 + 1 美元|护栏拦截 `PRICE_OVER_CAP`，任务「异常」，其他任务继续|
|配送时长超过上限|送达日期 = 洛杉矶今天 + 上限 + 1 天|护栏拦截 `DELIVERY_TOO_LONG`|
|商品缺货|护栏之前上报失败 `OUT_OF_STOCK`|任务「异常」|
|页面加载失败|上报失败 `PAGE_LOAD_FAILED`|首次自动重试一次，第二次「异常」|
|提交后结果不明|登记后上报 `unknown`，本批次结束|任务「结果待核实」，账号暂停执行|
|遇到验证码|上报失败 `CAPTCHA_ENCOUNTERED`，本批次结束|账号暂停执行，任务保留|

界面（页面内面板、弹出页、设置页）与日志里不出现原样的英文错误码：服务端错误码、护栏拦截码、尝试失败码、中止原因码、批次停止原因都换成中文说明（`core/codes.ts`）；认不出的码写「其他原因」。

## 写在代码里的几条规矩

这些是早期实现（amz-purchase-control）踩过的坑，移植时保留：

- **权限最小：只申请 `storage`、`alarms`，不申请 `cookies`、`tabs`。** 查亚马逊标签页按主机权限的地址过滤，用不着 `tabs`（它会让插件读到所有标签页的地址与标题）。不读也不上传 Cookie，不上传页面 HTML。身份只来自页面导航栏与内联脚本里的 customerId；上报的页面地址只有 origin + 路径，不带查询串。遇到验证码转人工，不做任何反检测。
- **设备令牌只在后台。** 令牌存在扩展源下的 IndexedDB（`background/secrets.ts`）：内容脚本跑在亚马逊页面的源下，读得到 `chrome.storage.local`、打不开那个库。早期版本写在 `storage.local` 的令牌，后台第一次读到时搬走。
- **后台没有模块级的租约状态。** MV3 后台空闲约 30 秒被回收，变量归零。标签页租约、当前批次、身份读数存在 `chrome.storage.session`，设置、日志、结果回执、当天定时记录存在 `chrome.storage.local`；「读 → 裁决 → 写」在串行闸里做。
- **后台标签页的定时器会被节流到约 60 秒一次。** 标签页租约有效期 5 分钟、持有者正在执行时再宽限 10 分钟（`core/lease.ts`，纯函数）；批次心跳按租约有效期算（默认 35 秒一次），引擎每一步之前也会按时钟补发，后台还有一路 30 秒的兜底心跳（只在执行页面对 `pc.ping` 答复「还在跑这个批次」、引擎最近还在动时才发）。
- **执行页面一刷新、一跳转、一关闭，引擎就没了，而且来不及说一声。** 后台不信本地的「正在执行」：同一标签页里来了批次开始之后加载的新页面（`pc.hello`）、执行页面离开（`pagehide` → `pc.bye`）、标签页关闭、执行页面对 `pc.ping` 不再答复，任何一个都让后台接管批次：界面上不再显示「正在执行」、放开标签页租约，立即通知服务端结束批次（服务端按租约过期同样处理在途尝试：未登记提交的回到已分配，已登记提交的进结果待核实并暂停账号），不等租约到期，也不再替它续租。插件安装、更新、浏览器重启时清掉留下的「正在执行」。
- **身份按页面加载先后对账（`core/identity.reconcileIdentity`）。** 导航栏是页面加载那一刻服务端渲染的，几小时前打开的页面重读一百遍也只是那一刻的样子：比先后只看页面的加载时刻；较早加载的页面的读数不能覆盖较新的；标签页关掉（或跳到下一页）后，若它是最新加载的一份仍留作证据；已登录但没读到买家号 ID 的读数不取代、也不作废读到 ID 或显示未登录的读数（例如显示另一个买家号的标签页跳到一张读不出 ID 的页面，另一个买家号仍是证据）；读数之间不一致时**绝不报「是绑定账号」**（报较新的、不是绑定账号的那一份：另一个买家号 → 不一致，未登录 → 未登录），开始执行之前让每个亚马逊标签页重读一次，有分歧就不开始，提示刷新或关闭较早打开的标签页。停在 `/ap/signin`（包括已登录时的重新验证页）的标签页读成未登录，同样按分歧处理 —— 往安全的一侧，关掉或完成验证后的下一次页面加载即恢复。
- **结果一定送到。** 后台在发出结果之前先存回执；引擎遇到没说上话或 5xx，在租约预算内按退避重发**同一份**结果（服务端按重复上报认出来），期间照常续租；结果没送到之前绝不结束批次（结束会把已登记的尝试判成结果待核实）。引擎放弃之后后台接管：续租、补交（第一次立即补交，之后按退避），送达后结束批次；租约预算用完、或接管满 10 分钟（与引擎重发结果的上限相同，例如续租成功而结果接口一直 5xx）还送不到就放手：不再续租、不替它结束批次，由服务端在租约到期后清扫在途尝试，回执保留、之后继续补交，最多 24 小时。补交的时机：插件后台启动时、每次心跳成功时（不等退避），以及 30 秒一次的回执闹钟（按退避）。服务端的答复：200（含同一份重复上报的 `duplicate: true`）→ 送达；尝试已是「结果待核实」、或已由控制台核实（已下单 / 未下单）而这份不同 → 409 `CONFLICT`、`detail.late_receipt_recorded=true`（回执已记下，供人工核实）→ 也算送达；其他 4xx（含别的 409）→ 服务端明确不收，不再发；5xx、没说上话 → 留着。提交登记永远不进回执、永远不补发。有回执没送到时不能解除配对。
- **三层互斥。** 本页单飞闸（重复点击、手动与定时同时触发只开一个）→ 本浏览器标签页租约（多个亚马逊标签页只有一个去申请批次）→ 服务端执行批次（跨电脑、跨浏览器的全局权威）。
- **HTTP 200 不等于业务成功。** 每个接口都校验响应形状；护栏只有 `verdict === "pass"` 才算放行；提交登记只认 HTTP 200。
- **只对「没说上话」重试，而且只对可以重复的请求。** 配对、开始批次、领取、护栏、提交登记不自动重试；结果、进度、批次心跳、结束批次在服务端 5xx（事务已回滚）或插件后台没有响应时也原样再发。提交登记的响应没拿到时，插件停止并停止续租，交给服务端清扫（已登记 → 结果待核实，账号暂停），绝不再登记或点击第二次；浏览器在连接断开后把同一个 POST 重发、服务端回「该尝试已登记提交」（409，`attempt_status=submitting`）时，插件明白这就是「已登记、没点击」，上报 `unknown` 并结束批次，不当成「被拒」。护栏拦截的响应丢了、重发得到「尝试已结束（失败）」时按拦截计，继续下一笔。
- **所有等待都有界。** 每个请求 15 秒超时；后台消息有上界；单批次最多领取 200 笔。
- **NULL 不是 0。** 读不到的金额、天数保持空值，交给服务端按「数据不可靠」拦截。

## 与契约的约定细节

- `POST /runs` 的返回：服务端给 `{run_id, lease_ttl_s, lease_expires_at}`，插件按 `lease_ttl_s` 定续租节奏；早期的 `{id}`、`{run: {id}}` 也认。
- `POST /runs/{id}/finish` 的 `reason` 恒为契约缺省的 `finished`，插件的细分原因放在 `detail`。
- 进度返回 `{continue, cancel_reason, cancel_code}`（契约 §5 第 7 步）：`cancel_code` 在 continue=true 时为 null，否则取 `UPSTREAM_CANCELLED` / `ACCOUNT_ARCHIVED` / `ACCOUNT_PAUSED` / `IDENTITY_MISMATCH` / `IDENTITY_STALE` / `SOURCE_HOLD` / `SOURCE_CHANGED` / `ATTEMPT_FINISHED`（上报规则见上表）。
- 领取返回 `{attempt: null, reason, retry_after_s}` 时稍后再领：`retry_after_s` 只要是不小于 0 的数就算（小数、数字字符串也认）。
- 身份单独上报用 `POST /plugin/v1/identity`（请求体为身份字段本身）；服务端没有这个接口（404 / 405 / 422）时改由心跳捎带。几分钟前读的、这一轮哪个标签页都没读到的身份结论不再当成「刚读到」上报（服务端看到的「最近上报」得是真的）。
- 配对的 429 `RATE_LIMITED` 读 `detail.retry_after_s`，没有时读 `Retry-After` 响应头。
- 插件上报的尝试失败码：`OUT_OF_STOCK`、`PAGE_LOAD_FAILED`、`CAPTCHA_ENCOUNTERED`、`ABORTED_UPSTREAM_CANCELLED`、`ABORTED_BY_SERVER`（只在服务端给了 `cancel_code` 时；服务端按中止类处理）、护栏拦截码（原样；护栏没给拦截码时 `GUARD_BLOCKED`；提交前复核护栏不过时取 `detail.block_code`），以及少见的 `SUBMIT_REJECTED`（登记被拒且不是上游取消、也不是复核护栏不过）、`PLUGIN_SIMULATION_ONLY`（服务端下发了非模拟尝试，插件拒绝执行；账号级，服务端暂停账号，本批次结束）。
- 批次心跳的 `stop=true` 在当前这一笔结束后生效（模拟的一笔在毫秒级完成）。真实驱动接入时需要在每一步之间检查。
